# Code of Conduct

## Our standard

This project exists to help people reason carefully about untrusted code. The
same care applies to how we treat each other.

Be direct about technical disagreements and generous about people. Critique
analysis, evidence and code — not the person who wrote it. Assume the other
person is competent and acting in good faith until you have specific reason to
think otherwise.

## Expected behaviour

- Give feedback that is specific and actionable.
- Say what you actually verified, and what you only assumed.
- Accept correction without defensiveness, and correct others without contempt.
- Respect that people contribute at different levels of experience and available
  time.

## Unacceptable behaviour

- Personal attacks, harassment, or discriminatory language of any kind.
- Publishing another person's private information.
- Sustained disruption of discussion, or bad-faith argument.
- Using this project's issue tracker to coordinate harassment of a package
  author. **A PackageGate finding is evidence for a human to evaluate, not a
  verdict, and it is never a licence to attack a maintainer.**

That last point is specific to what this tool does. Supply-chain analysis names
real people's work. A false positive here can damage a maintainer's reputation
unfairly, which is precisely why the project treats false positives as its
central risk. Report suspected malicious packages to the registry and the
relevant security teams, not by pile-on.

## Scope

Applies in all project spaces — issues, pull requests, discussions — and when
representing the project publicly.

## Reporting

Report unacceptable behaviour privately to the maintainers via GitHub. Reports
will be reviewed and handled discreetly. Maintainers who do not uphold this code
may face consequences determined by the other maintainers.
